Cut this roundChanged

The separate Outstanding Tasks panel is gone.

Round 1 put an aggregate of Tasks on the History screen. With attention formalised, the Needs you view is that aggregate — every Conversation in it is there because it has open Tasks or an unresolved Input Request. Two views of one truth, sitting on the same page, would invite them to disagree.

Load older, not infinite scroll

An explicit control at the end of the list, advancing the cursor.

Infinite scroll fights everything this surface is: it makes the end of history unreachable, breaks restoring position on back, and steals focus placement from keyboard users mid-triage. Cursor paging behind a button keeps the architecture honest without any of that. Virtualisation stays out until measured volume earns it.

02

Search and filter treatment

Q2 decided
Search is present, not prominent. It ships in first production because a Business Subscriber needs it, but it must not turn a Consumer’s twelve Conversations into a database browser. One field, quiet at rest, that grows into the primary control only once a query is active.
Resting state

A single compact field in the header. No filter panel, no result count, no sort control.

Results stateProvisional

Date grouping is suppressed while a query is active. Results become one flat ranked list under “N results for “…””, with a clear control.

Grouping a result set by date fights relevance — the reader is looking for one Conversation, not for last Tuesday. Restoring grouping on clear makes the two modes legible as modes.

Filters — exactly two

FilterBehaviourNote
DateRange, written to ?from= / ?to=The only filter a Consumer is likely to touch.
ChannelMulti-select, written to ?channel=Data-driven from Channel reference data — never a hardcoded list, and never a phone/other binary. Renders product labels (Phone Call, In-app Voice, Text Chat), not internal identity (telephony, voxi_app).
state · participant · outcome · attentionNot shippedAttention already has a view switch; outcome has no attention meaning and belongs on the detail page. Adding these would build the enterprise panel the thesis rejects.

With one channel live, the control renders a single option. That is correct and deliberate: a data-driven control that happens to have one value is not the same as a control that assumes telephony, and only the first survives voxi_app shipping.

03

Date grouping and pagination

Decided
Grouping

Today · Yesterday · Earlier this week · Older, then calendar dates within Older.

Set in the type.label token — 11px/700/1.2 uppercase — the section device the mockup already established. Sticky at ≥ lg, with a matching scroll-margin-top on every row so a focused row is never covered (WCAG 2.4.11). Suppressed while search is active.

Pagination

Cursor. Never load a Subscriber’s whole history into one client array.

Appending a page must not move existing rows or steal focus: new rows land below, the control stays where it was, and the count announces politely. Virtualisation is deferred until the rendered list actually earns it.

04

Conversation row anatomy

Changed
Conversation row            the whole row is one link, one tab stop
  ├── Attention marker        present only when it needs you
  ├── Identity               saved name, else the number — never a role noun
  ├── Channel tag            quiet, always present, product label
  ├── Time
  ├── Subject                one line, Voxi-authored, truncates
  ├── Primary state marker   only when not Ready — Live / Processing / Failed / Enrichment failed
  ├── Degraded marker          independent; composes with any of the above
  └── Task count              lime when cleared
One component, two densities — and density follows layout, not tier. In the narrow list pane of the two-pane desktop layout the row is compact: identity, subject and markers on one line. In a full-width single column it is comfortable: subject on its own line with room to breathe.
Why not switch on volume

Densifying because a Subscriber crossed a row count means the interface changes shape underneath someone who did nothing. Binding density to the container instead is deterministic, testable, and gives the busy Subscriber the compact list anyway — because triaging volume is exactly what the two-pane layout is for.

Why not a density toggle

A preference nobody asked for, persisted somewhere, tested in two states forever. The layout already answers the question.

The channel tag stays even at 99% telephony. Hiding it while one channel dominates is precisely how Call quietly becomes the universal parent again.

05

Conversation detail hierarchy

Approved order
  1. Identity · time · channel
    Who Voxi spoke with, when, over what.
  2. Subject
    One Voxi-authored line. The decision point for reading further.
  3. Response slot New
    Input Requests first, then state banners. Empty and absent when the Conversation is Ready and undegraded.
  4. Summary
    Voxi speaking. The primary read. agentCard, mint outline.
  5. Tasks
    Yours to clear.
  6. Transcript
    Supporting evidence, collapsed by default.
  7. Channel-specific details
    Telephony facts. Present only for a Call.
Why the response slot sits above the Summary

The approved hierarchy orders the record. An Input Request is not part of the record — it is an open request from Voxi that is blocking resolution.

Placing it below the Summary would have the Subscriber read the outcome before learning the outcome is incomplete pending their answer. The slot is a container, not a new hierarchy level: when a Conversation is Ready and undegraded it does not render, and the approved order is exactly what remains.

The reading measure holds here at every width. The list densifies with volume; the Summary and Transcript never do. A Business Subscriber having more Conversations is not a reason to make each one harder to read.

06

How the states compose

Three axes
Primary state answers “can I read this yet?”. Degradation answers “how well did Voxi do?”. Two different questions, so two different slots — never merged into one badge, never pre-composed into a single status enum.

Primary state — lifecycle × enrichment, mutually exclusive

StateDerived fromTranscriptSummaryTasksOutcome
Liveactive————
Processingcompleted + pending|processingyesbeing writtenbeing derivedyes
Readycompleted + completedyesyesyesyes
Enrichment failedcompleted + failedyesnonoyes
Failedfailedpartial, if anynonono

Nothing in the “no” column is ever fabricated to make a page look complete. A Failed Conversation shows the evidence that genuinely exists and says plainly that Voxi could not complete the Call — no invented Summary, no empty Task list implying zero Tasks, no outcome.

Degradation — independent, composing, 1..N

What it is

Voxi continued with reduced capability because part of the published runtime was unavailable. It happens at bootstrap, not during enrichment.

A fully enriched, perfectly readable Conversation can still be degraded. Ready + Degraded, Processing + Degraded and Enrichment failed + Degraded are all valid and all render both marks.

How it renders

A separate marker on the row and a separate banner in the response slot, naming what Voxi could not do — read from structured degradation records.

More than one skill can degrade in one bootstrap, so the banner handles a list, not a boolean. The reason is never parsed out of error prose — ADR-0006 forbids it, and the database stores the fields precisely so the UI does not have to.

ADR-0006: degradation must never become quiet routine. It is therefore never styled as ambient chrome, and never suppressed because the Conversation otherwise looks fine.

Call failed Voxi couldn’t complete this call Showing what was captured before it stopped

07

Task treatment

Decided
Shape

Checkbox, text, source line. Completable from the detail page and inline from the list.

A Task always belongs to a Conversation. There is no global “add Task”, no standalone Task creation on this surface, and no Task that exists without a source to link back to.

Completion

Optimistic: the checkbox fills lime, attention recalculates, the request follows.

On failure, revert and say so inline. A silently reverted checkbox is worse than a slow one — the Subscriber walks away believing they cleared something they did not.

Clearing the last Task does not eject the Conversation. It stays exactly where it is, visibly settling, until the Subscriber navigates away or changes view. In the two-pane layout this is stronger still: the open Conversation must never vanish from the list pane while it is being read.

08

Input Request treatment

Q9 decided
Product distinction

Task — something I need to do.
Input Request — something Voxi needs from me.

Both feed attention independently. A Conversation carries 0..N Input Requests, each answerable on its own.

The answer is submitted against this specific request. No general composer, no threaded reply system, no standalone messaging surface — those would turn a bounded question into a chat product as a side effect.

Voxi needs your input Which account should I use for this? Sarah asked to be invoiced but didn’t say which business. Answer Voxi Illustrative composition — visual treatment not locked

After answering

The request resolves, attention recalculates, and the block collapses into a settled record showing the question and the answer given. It does not disappear: what the Subscriber told Voxi is part of what happened, and losing it would make the Conversation unreadable later.

What happens next is genuinely unresolved. If Voxi needed input to resolve something, answering presumably lets it finish — which would return the Conversation to Processing and produce a new Summary. Whether that is the behaviour is a product decision. Open · Q10

The renderer never assumes turn.textChanged

A Turn renders as an ordered list of its content parts, even when telephony reliably produces exactly one text part.

Building around one string per Turn is the shortcut that has to be unwound the day an Email Turn arrives carrying a body plus a PDF plus a spreadsheet. The iteration costs nothing now.

Lifecycle events are not Turns

There is no system role, and none is wanted.

“Call ended”, “integration failed”, “processing completed”, “runtime degraded” are structured state. They render as state, in the response slot or the Call details — never interleaved into the Transcript as pseudo-turns.

No realtime audio, ever, as history. Voxi does not record or retain the audio of a Phone Call or an In-app Voice Conversation; the durable record is textual. Asynchronous audio sent as message content — a WhatsApp voice note — is a different thing and may persist as its own Content Part, but that channel is not in first production and no placeholder for it appears in this shape.

Empty, All clear and Needs you

Provisional
No Voxi Number

Onboarding is unfinished. Point at completing setup, not at an empty list.

Number live · no Conversations

Say what will happen when someone calls. Anticipation, not emptiness.

All clear

Nothing needs you, history exists. A calm line at the top of the list — not a full-screen moment.

Steady stream

Needs you > 0, the normal Business state. Must read as a manageable queue, never as an alarm.

Filtered / search empty

Distinct from having no Conversations. Names the active filters and offers to clear them.

Load error

What failed and what to do. Retry preserves filters. Never an empty list posing as “no results”.

The product must not depend on seeing zero. All clear is common for a Consumer and may be rare for a Business Subscriber. Health cannot be expressed only as an empty state, so the Needs you view has to feel calm and finite when it is full — which is what the reading measure, the date grouping and the absence of alarm colour are all doing.

13

Open questions that block implementation

Open

Three. Everything else carried from round 1 is closed, deferred, or answerable during build.

Q10
Does answering an Input Request re-run enrichment?
If Voxi needed input to resolve something, answering presumably lets it finish — which returns the Conversation to Processing and replaces the Summary. If it does not, the answer is recorded and nothing else changes. Blocks the detail page: the post-answer state is either a transition or a dead end, and they look nothing alike.
Q11
Does a Live Conversation stream Turns into the UI?
Final Turns are persisted as the Conversation runs, so showing them live is possible. Recommendation: no in first production — Live shows identity and “Voxi is on this call now”, nothing more. Streaming would put a realtime subscription on the detail route for a state that lasts a couple of minutes. Blocks: whether the detail route needs realtime at all.
Q12
What is searchable?
Subject, Summary and participant identity are certain. Transcript content is the question — it is the most useful thing to search and the most expensive to index. Blocks: the empty-result copy, result ranking, and what the DB worktree has to index. The product says what is searchable; the index shape stays theirs.
Closed since round 1

Q1 participant noun — no longer needed; Caller for telephony, identity elsewhere. Q2 volume — asymmetric. Q3 enrichment retry — none in first production. Q4 handled state — no, attention stays derived. Q5 Tasks view — deferred; the Needs you view covers it. Q6 degraded copy — specimen above, wording open but not blocking. Q7 call back — a tel: link or nothing; not blocking. Q8 cardinality — one Account, one Subscriber. Q9 input — narrow reply affordance.
